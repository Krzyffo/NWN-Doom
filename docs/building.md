# Building NWN-Doom from source

For playing, or adding NWN-Doom to a module, the release zips are enough;
see the [README](../README.md). This page is for changing the scripts or
the art.

You need Python (`py`), the NWN:EE toolset (`bin\win32\nwtoolset.exe` in
the game folder) and a Doom WAD, normally the official
[Freedoom](https://freedoom.github.io/) `freedoom2.wad`.

## 1. The art hak

```
py tools/wad_to_hak.py path\to\freedoom2.wad
```

Extracts the status bar, digits, Doomguy's faces, weapon sprites and the
pistol, shotgun, punch and imp fireball sounds, writes
`build/nwn_doom.hak`, copies it to your NWN `hak` folder and regenerates
`src/doom_art.nss` (sprite positions). id's `doom.wad` / `doom2.wad` work
too, but releases use Freedoom, whose licence allows shipping the art.

- Use the official `freedoom2.wad`: some repacked WADs ship empty sound
  stubs or blank faces. The tool warns about silent sounds and skips blank
  faces.
- The sounds play through rows 10100-10105 that the tool appends to the
  game's `visualeffects.2da` in the hak (`DOOM_VFX_*` in `doom_art.nss`):
  applying an effect plays reliably, while `PlaySound` depends on the
  playing object's action queue. Another hak that also replaces
  `visualeffects.2da` conflicts.

## 2. The scripts

```
py tools/build.py
```

Compiles `src/` with Beamdog's `nwn_script_comp` and writes
`build/nwn_doom.erf` (sources plus compiled `.ncs`). Run it again whenever
a script changes. The compiler comes from the
[neverwinter.nim releases](https://github.com/niv/neverwinter.nim/releases)
(`neverwinter-x86_64-windows.zip`), unzipped into `tools/neverwinter/`.
Without it, `py tools/build_erf.py` packs the sources only and the toolset
compiles them.

## 3. The test module

1. In the toolset, **File > New** and run the Area Wizard for a module
   with one area (a small interior tileset such as Crypt or Castle
   Interior works best). Save it.
2. **Edit > Module Properties > Custom Content**: add the hak `nwn_doom`.
3. **File > Import...** `build/nwn_doom.erf`. Re-importing later asks to
   overwrite; say yes.
4. **Module Properties > Events > OnModuleLoad**: `doom_modload`. It wires
   up the other module events itself and runs the stock `x2_mod_def_load`.
5. **Module Properties > Advanced > Variables**: an `int` `DOOM_WAVES` = 1,
   or no waves spawn.
6. Optional: paste [module_description.txt](module_description.txt) into
   **Module Properties > Description** (shown on the module selection
   screen), and place waypoints tagged `DOOM_SPAWN` where monsters should
   appear (otherwise they spawn 10-15 m around the player).
7. **Build > Build Module** with "Compile scripts" ticked, check for
   errors, save, and **File > Test Module**.

The module and the hak live in your NWN user folder (`modules`, `hak`),
normally `Documents\Neverwinter Nights`; the `[Alias]` section of `nwn.ini`
can move it. Logs are under `logs`.

## Where the tools look for the game

No paths are stored in the repository. `tools/nwn_paths.py` finds:

- **The game's install folder** (the one with `data` in it): from the
  `NWN_ROOT` environment variable, else your Steam libraries. The script
  compiler and `nwn_key.py` need it.
- **Your NWN user folder:** from `NWN_USER` (or `NWN_HOME`), else
  `Documents\Neverwinter Nights`. `wad_to_hak.py` installs the hak there,
  `package.py` reads the module from it, and `doom_quickbar.py` finds
  characters in it.

If the game or the user folder is somewhere else, set the variable once and
open a new terminal:

```
setx NWN_USER "D:\Games\NWN user folder"
```

The WAD for `wad_to_hak.py` is given on the command line, or with the
`DOOM_WAD` variable.

To add the scripts to an existing module instead, follow
[adding_to_a_module.md](adding_to_a_module.md) with `build/nwn_doom.erf`.

## 4. Packaging a release

```
py tools/package.py --module NAME --version X.Y
```

Writes two zips to `build/dist/`:

- `NAME-X.Y.zip`: `NAME.mod` from your modules folder and the installed
  `nwn_doom.hak`, laid out like the NWN user folder (`modules/`, `hak/`),
  plus a `README.txt` (install steps and `module_description.txt`).
- `nwn-doom-kit-X.Y.zip`: the hak, the compiled scripts
  (`erf/nwn_doom.erf`) and the tutorial, for builders.

Both include `FREEDOOM-LICENSE.txt` and `FREEDOOM-CREDITS.txt`: Freedoom's
BSD licence requires its notice to ship with the art.

It refuses to build if the module does not use the hak, OnModuleLoad is
not `doom_modload`, `DOOM_WAVES` = 1 is missing, or a `doom_*` script is
not compiled in, and warns if the description is empty. It cannot tell
whether the compiled scripts are the latest build, so import the latest
`build/nwn_doom.erf` and build the module first. Nothing is uploaded;
publish the zips yourself (GitHub release, Neverwinter Vault).

## Repository layout

- `src/`: NWScript sources. `doom_inc.nss` holds the tunable constants;
  `doom_art.nss` is generated by `wad_to_hak.py`.
- `tools/wad_to_hak.py`: WAD art and sounds to the hak.
- `tools/build.py`: compiles and packs the scripts.
- `tools/package.py`: checks the module and builds the release zips.
- `tools/doom_quickbar.py`: puts the `/1` `/2` `/3` weapon macros on a
  character's F1-F3.
- `tools/build_erf.py`: ERF/HAK writer; `--list <file>` shows an archive's
  contents.
- `tools/nwn_key.py`: lists or extracts stock resources from the game's
  KEY/BIF archives, e.g. `py tools/nwn_key.py list "nw_imp*" --type utc`.
- `tools/nwn_paths.py`: finds the game and your NWN user folder for the
  other tools (see [Where the tools look for the game](#where-the-tools-look-for-the-game)).
- `docs/`: this page, [how_it_works.md](how_it_works.md),
  [adding_to_a_module.md](adding_to_a_module.md) and
  `module_description.txt`.
- `licenses/`: Freedoom's licence and contributor list, shipped with the
  art.
